## 1. What was implemented

- **Homepage wiring.** `src/App.jsx` now mounts the shared `NorthernLightsThreeNight` (surface `"homepage"`) inside the existing `#northern-lights` wrapper, replacing `NorthernLightsCard`. It receives the real homepage `t`, `lang`, `entitlements`, `theme` and `startCheckout`. The real authentication-loading signal is `useMe()`'s `loadingMe` (verified in `src/hooks/useMe.js`; App.jsx previously did not destructure it) and is forwarded, so no exposure event records a premature Free guess. The anchor, the `isAuroraSeason()` off-season sibling fallback and the module's position (below the decision surface / Weather Voice) are unchanged. Exactly one data owner is mounted; the old card is not kept alongside it.
- **Surface prop.** `surface` (`"landing"` default | `"homepage"`) is the only fork. On the homepage: Free sees the compact hint plus one upgrade button (no landing marketing block, no second upgrade block); details preference uses the key the retired homepage card used (`nl_details_expanded`), landing keeps `nl3_details_expanded`, so neither surface inherits the other's expanded state and Free has no hidden content to expose; the landing-only `northern_lights_landing_cta_clicked` event is never emitted.
- **Navigation.** The homepage module renders a real router `Link` to `/en/northern-lights?date=<selected evening>` (`nl3-details-link`), always the selected slot (unavailable/expired included), never the recommended date. IS copy: "Sjá nánar á ensku síðunni"; EN copy: "See full details for this night". No new route; landing stays forced English.
- **Landing query handling.** New `src/lib/auroraNightQuery.js` (`parseNightQueryDate`, `buildNightDetailPath`, `withNightQueryDate`). `NorthernLightsLanding.jsx` uses `useSearchParams`: it passes a single exact calendar-valid ISO date as `requestedDate`; the hook (`useAuroraThreeNight`, new optional `requestedDate` input) seeds the initial selection from it when it is one of today's three slots, re-applies it only when it actually changes (back/forward), and otherwise selects tonight. Selection is mirrored to the query with router `replace`, preserving unrelated params; route entry without a date writes nothing; a present-but-unusable date (impossible, duplicate, malformed, out of window) is normalized to the selection; midnight normalization also rewrites the query. Neither direction emits a selection event and the sync is one-directional per change (no URL/state loop, no refetch). Canonical SEO URL (no query) is untouched.
- **Analytics.** `northern_lights_night_selected` now carries `source: homepage|landing`; `northern_lights_best_night_viewed` and `northern_lights_multi_day_upgrade_clicked` carry `source` too; all other fields unchanged. `northern_lights_landing_cta_clicked` is guarded to the landing surface only. Checkout still receives `northern_lights_card`. The details link is navigation, not a selection.
- **Comments/tests requested by Jonesy.** Stale header comments in `NorthernLightsThreeNight.jsx` and `AuroraNightOutlook.jsx` now describe shared homepage/landing use; the App.jsx anchor comment was updated too. `App.northernLightsAnchor.test.jsx` (real App, real module) and `NorthernLightsLanding.cardWiring.test.jsx` were inspected against source and updated (details below). `App.weatherFinderSelection.test.jsx` and `App.weatherVoiceIntegration.test.jsx` stubbed the old card and had to be repointed to the shared module stub (unrelated-suite network isolation only).

## 6. Limitations

- **Playwright's headless Chromium here has no Icelandic ICU locale data** (`Intl.DateTimeFormat("is-IS")` resolves to `en-US`), so the day-2 tab label showed "Monday" in the IS module. Node-based unit tests confirm the Icelandic weekday path ("sunnudagur" etc.); regular Chrome ships `is` locale data. A browser without it would show an English weekday on the IS homepage. Not fixed (out of scope; would need a translation-owned weekday table).
- The full-page landing screenshots captured after scrolling show the sticky header overlaying the middle of the page — a Playwright full-page/sticky artifact, not an app defect (the module content itself is correct).
- IS copy (`nlHomeDetailsLink` and the earlier #423 strings) has had no native-speaker review.
- No live Vedur.is/Open-Meteo/DB/cron validation (not authorized/required); everything above uses deterministic fixtures.
- The homepage back-navigation from landing remounts the homepage module, so its selection resets to tonight (the module has no persisted selection by design; the prompt asked only for homepage → landing carry-over).
- The legacy `NorthernLightsCard.jsx` and its tests remain in the tree unused, by instruction.
