## Mutation demonstration (R1/R2-class regression proof) — now a persisted, runnable script

v5 performed this inline during development, described but not persisted, and only covered the ledger half — Jonesy's R2(e) correctly flagged this as not actually delivered. This round persists both halves as `test/test_mutation_regressions.py`, run as part of the standard suite (see `README.md`'s "Exact commands run this round").

1. **Raw-request-URL ledger regression.** A scratch copy of `ledger.py` has `reserve_attempt()` mutated to accept a `raw_url` parameter and store it verbatim in the attempt record (iteration-3's exact defect shape). Calling the mutated copy with a synthetic key-bearing URL **leaks the key into the ledger file — RED, confirmed** this round. The real, unmutated `ledger.reserve_attempt(path)` takes no such parameter at all and the ledger stays clean — **GREEN, confirmed**. `ledger.py`'s own SHA-256 is identical before and after the whole exercise (see `test/test_mutation_regressions-output.txt` for the actual hash printed).
2. **Raw-exception-output regression.** A scratch copy of `transport_core.py` (the layer actually responsible for discarding raw exception text in this architecture — not `child_worker.py`, whose own `except Exception:` branch is unreachable for a connect-level fault once `transport_core.request()`'s own catch-all is in place) has its outer catch-all mutated to fold `str(e)` into the returned category instead of discarding it (the `do_fetch.py`-style defect). Running the real, *unmodified* `child_worker.py` against this mutated copy (via `sys.path` ordering, never editing `child_worker.py` itself) **leaks the fake secret+URL into stdout — RED, confirmed**. The real, unmutated `transport_core.py` stays clean against the identical injection — **GREEN, confirmed**. `transport_core.py`'s own SHA-256 is identical before and after.
