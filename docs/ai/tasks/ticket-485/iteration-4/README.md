## Architecture

| File | Role |
|---|---|
| `provider_target.py` | The ONE fixed, immutable destination (`customer-api.open-meteo.com:443/v1/forecast`) as module constants — no function, no parameter, nothing for any caller to override. |
| `limits.py` | The single frozen source of truth for every cap/deadline (`PROVIDER_ATTEMPT_COUNT_CAP`, `DECODED_CAP_PER_ATTEMPT`, `DECODED_CAP_TOTAL`, `RUN_WINDOW_S`, `TOTAL_DEADLINE_S`). `ledger.py`, `pipeline.py` and `child_worker.py` all source their limits from here, never redefine them independently. |
| `secret_policy.py` | `validate_and_encode(secret)` — rejects non-string/empty/overlong/non-ASCII/control-or-forbidden-character secrets with a fixed category *before any attempt*, then percent-encodes a valid one with a real query encoder (`urllib.parse.quote`). Shared verbatim by `child_worker.py` and `test/test_transport_child.py`, so the policy itself cannot diverge between production and test. |
| `schema.py` | Strict parameter allowlist/validation — exact canonical field names/order, typed value checks, enum checks, ASCII/length/delimiter checks — run BEFORE any socket or ledger attempt. Rejects a caller-supplied `apikey` in any case variant. Every rejection raises `SchemaViolation(category, field)` whose `str()` is always exactly `"{category}: field={field}"` — the caller's raw value is never echoed. |
| `leak_scanner.py` | Bounded secret-leak detection: raw, percent-encoded (any hex case), double percent-encoded, backslash/JSON-escaped forms. A malformed/undecidable escape sequence is treated as `UNDECIDABLE` and fails CLOSED (counted as a match), never silently skipped. Bounded protection of the forms listed — not a claim of covering every conceivable encoding. |
| `transport_core.py` | The shared, parameterised (host/port/path) DNS+TCP+TLS+HTTP+bounded-decompression primitive, stdlib-only (`socket`/`ssl`/`http.client`/`zlib`). `request()` accepts no `ca_file`/`verify` parameter at all; the TLS context is built by a separate `_create_tls_context()` function (hardcoded to `ssl.create_default_context()`), monkeypatchable only from within test-only processes. **v7 (R4):** `TransportError` now carries `bytes_decoded_so_far` — the honestly-observed partial decoded-byte count at the moment of a read-phase failure, surfaced for truthful ledger accounting (never used to charge less than the full reserved cap for an incomplete transfer). |
| `child_worker.py` | **Production** child-process entry point. Imports `provider_target` (fixed), `secret_policy`, `limits`, `transport_core`; reads secret+query via stdin only; never imports anything under `test/`. Clamps the parent's requested decoded-cap to `limits.DECODED_CAP_PER_ATTEMPT`; encodes the secret via `secret_policy.validate_and_encode()` exactly once. **v7 (R4):** reports `TransportError.bytes_decoded_so_far` as the outcome's `bytes_decoded` on failure, instead of hardcoding 0. |
| `ledger.py` | Durable, atomic, **parent-only** ledger. The child process never imports this file at all. A durable `terminal` flag, once set, permanently blocks every future `reserve_attempt()` against this file, across process restarts. **v7 (R2):** `reserve_attempt()` also refuses with the new `LedgerIncomplete` if ANY existing attempt is not `status=="complete"` — not just when terminal; new `finalize_attempt()` sets an outcome AND (if given) the terminal flag in ONE atomic locked write, never two separate writes with a crash gap between them. **v7 (R3):** the Windows-unsafe `os.kill(pid, 0)` liveness probe and ALL automatic stale-lock reclaim are REMOVED entirely — a lock file that exists is always `LedgerBusy`, unconditionally, manual cleanup only; lock acquisition checks the lock file's *existence* only, never reads/parses its PID content (a real race the content-reading version had). **v7 (R4):** byte charging is derived from the outcome's own `category` (only `"OK"` reconciles to the verified count; every other category charges the full reserved cap, regardless of any partial `bytes_decoded` reported) — not a caller-supplied `bytes_known` flag anyone could get wrong; `reserve_attempt()` now computes and stores the REAL `min(per-attempt cap, remaining global budget)` as `reserved_decoded_cap`, queryable via the new `get_reserved_decoded_cap()`. **v7 (R5):** the old `_post_fsync_pre_replace_hook` test seam is REMOVED from this file entirely. `LEDGER_PATH` remains a fixed module constant in `pipeline.py`, never caller-supplied. |
| `pipeline.py` | Parent-side orchestration (`run_request()`): validates params, reserves the ledger attempt BEFORE spawning the child, spawns `child_worker.py` as a real OS subprocess with a hard total deadline, kills+joins it if exceeded, leak-scans everything the child returns (and its stderr) before persisting anything. `run_request(param_pairs, secret)` is the *entire* public signature. `_dispatch_child_and_collect()` is genuinely side-effect-free regarding samples — it only validates (`_validate_and_scan_sample`, no file I/O) and returns the result; the PARENT (`run_request()`) classifies and writes, to a filename unique per attempt ID (`_write_unique_sample`, never overwriting a different attempt's sample), using the single atomic `ledger.finalize_attempt()` call for the outcome+terminal+sample-metadata write. Dispatches the child with `ledger.get_reserved_decoded_cap()`'s real MIN-capped value. **v8 (R1/R2):** sample classification is now FOUR-way, not two: `SAMPLE_VALID` (written, non-terminal, with a dropped-unknown-field count in `sample_reason`), `SAMPLE_INCOMPLETE` (well-formed but no usable forecast — non-terminal, no sample), `SAMPLE_UNSUPPORTED_TOP_LEVEL_LIST` (the documented multi-coordinate response shape — non-terminal, no sample, out of scope for this single-location candidate), and `SAMPLE_STRUCTURAL_FAILURE` (secret, non-JSON, or an invalid stored-field type/value — the ONLY one that overrides the category to `UNSAFE_SAMPLE_REJECTED` and is terminal). `_validate_sample_shape()` now DROPS (never stores) an unrecognised top-level field and counts it, instead of raising — v7's version rejected documented, normal response fields as if they were unsafe. The documented fields `utc_offset_seconds`/`timezone`/`timezone_abbreviation` are now allowlisted with type checks; `hourly.time` entries are validated as strictly increasing/unique in the documented format. New `_is_complete_forecast()` requires `hourly.time` plus all six `schema.REQUIRED_HOURLY` arrays and matching `hourly_units` — `{}` no longer passes as a "valid" sample. The secret scan inside `_validate_and_scan_sample()` now covers the FULL parsed structure (including fields about to be dropped), not just the allowlisted subset, so an unknown field can never smuggle a secret past the gate. |

## Bugs found while building this round's own tests (disclosed, not hidden)

**From the v6 round** — three genuine defects found and fixed while writing v6's new real-execution tests, none in Jonesy's Round-1 R1–R7 list:

1. **`_dispatch_child_and_collect()` had an internal ledger side effect.** Its own disclosure-leak-scan called `ledger.mark_terminal()` against the hardcoded production `pipeline.LEDGER_PATH` directly. Any direct call to this private function (even `test_adapter.py`'s narrowly-scoped transport-mechanics tests) would durably terminal-mark the *real* candidate's ledger file as an unintended side effect. **Fixed** (v6): terminal-marking happens in `run_request()` itself, after dispatch returns or raises; the private function has no ledger coupling at all.
2. **`ledger.py`'s exclusive lock treated resolved contention as ambiguous.** A lock file that disappears between `os.open()`'s `FileExistsError` and the subsequent owner-PID read (because another process released it normally in between) was treated as `LedgerAmbiguous` — a false positive. **Fixed** (v6): that disappearance triggers a retry, not an exception.
3. **`_validate_sample_shape()` silently dropped unrecognised top-level fields instead of rejecting them.** **Fixed** (v6): any such field now raises `ValueError`.

**From this v7 round** — two more, found while re-testing after the R3 lock rewrite and while running the full suite repeatedly:

4. **A new race in the lock's PID-content check (found immediately after removing the liveness probe).** With the liveness probe gone, the lock code still tried to *read and parse* the lock file's PID content to distinguish "vanished" from "unparseable." Under real 6-process contention, a concurrent reader could see the lock file in the narrow window after `O_CREAT|O_EXCL` created it but *before* its owner finished writing+flushing the PID into it — an empty/partial read that doesn't parse as an int, misclassified as `LedgerAmbiguous` instead of ordinary busy contention. **Fixed**: lock acquisition now checks the file's *existence* only, never reads or parses its content at all (R3 already means the content is never used for any decision, so there was nothing left that needed reading). Covered by `test_ledger_concurrency.py` (0 errors across 5+ repeated runs after the fix, versus intermittent spurious `LedgerAmbiguous`/`LedgerBusy` confusion before it).
5. **An intermittent, environment-specific `shutil.rmtree` artifact.** On this Windows/Git-Bash setup, `shutil.rmtree(path, ignore_errors=True)` occasionally removes every file inside a scratch directory (e.g. under `tmp/e2e_copies/` or `tmp/mutation/`) but leaves the now-empty directory shell itself behind, silently (the error is swallowed by `ignore_errors=True`). Observed a handful of times across many repeated full-suite runs this round. Not a defect in this candidate's own logic — the same general class of quirk as the previously-disclosed OpenSSL `%SystemDrive%` side-effect — cleaned up manually each time it was noticed, disclosed rather than silently hidden.

## Known, disclosed limitations (candidate is PARTIAL by its own design in these respects)

- No real provider request has ever been made — `customer-api.open-meteo.com`'s actual TLS chain, response shape, and whether this candidate's raw-socket HTTP/1.1 construction is fully compatible with it, are all **unverified**. A live probe needs its own, separately reviewed scope.
- `transport_core._read_response`'s minimal `http.client.HTTPResponse` shim has been tested against a local `http.server` only; real-world HTTP/1.1 edge cases (chunked transfer-encoding variations, trailers, unusual header folding) are not exhaustively covered.
- The leak scanner is bounded (raw/percent/double-percent/JSON-escape, depth-limited) — explicitly not a claim of covering every conceivable encoding. Base64/hex/HTML-entity/reversed/`+`-as-space forms are not detected (unchanged disclosure from v5).
- Geometry/direction/ETA repair is explicitly out of scope for this round, unchanged from earlier iterations.
- This candidate's real-world DNS-stall test patches `socket.getaddrinfo` inside a TEST-ONLY child script to force a stall — proves the parent's kill/join mechanism works when DNS misbehaves, not behaviour against a real misbehaving public DNS resolver (untestable offline by design).
- **Availability tradeoff, accepted deliberately (R3):** the ledger lock has NO automatic stale-lock reclaim of any kind as of v7. If a process holding the lock crashes without releasing it (e.g. killed by something other than this candidate's own code, or a host-level failure), the lock file is left behind permanently and every future `reserve_attempt()` call will raise `LedgerBusy` until a human manually removes the lock file after confirming the owner process has actually exited. This trades availability for safety: the previous (v6) automatic-reclaim design used `os.kill(pid, 0)` as a liveness probe, which Jonesy's Round-2 review found is not a safe passive existence check on Windows (signal 0 there is closer to `CTRL_C_EVENT`/a terminate path than a no-op probe) and could have signalled the very process holding the lock. No replacement liveness mechanism (e.g. a proper `OpenProcess`/`GetExitCodeProcess` check via `ctypes`) was implemented this round — manual cleanup is the only path.
- The network guard (`test/_network_guard.py`) only recognises literal loopback addresses (`127.0.0.1`, `::1`) as allowed — it deliberately does not resolve `localhost` or any other hostname, even a conventionally-safe one, since doing so would itself be a real resolver call. Every test server in this suite binds to `127.0.0.1` explicitly for this reason.
- **Byte-accounting cost of a blip, intentionally retained (v8 R3, decision not a code change):** because any non-`"OK"` outcome charges the FULL reserved per-attempt cap (v7's own R4 design), two transient failures (e.g. a connection reset) can exhaust the entire 4 MiB total budget even though far fewer bytes actually moved. For a paid single/double-probe live scope this means essentially no retry margin on a blip. This is accepted, bounded-research behaviour, not loosened here — any future live-probe scope must explicitly accept this cost rather than discover it live.
