## Wrapper execution-discipline limitations (R3, new this round — report-only, `harness/wrapper.py` itself is frozen/untouched)

`cc-report.md` (v1) described protections the code does not fully implement. Corrected here, not in the (frozen) code:

- The per-class exchange count and decoded-byte total are incremented in `append_outcome`, not in `reserve` — a hard crash between reserving an attempt and recording its outcome would leave that attempt present in `attempts` but NOT counted against budget on a subsequent run. The real run completed cleanly (8/8 outcomes recorded), so this did not actually occur, but the wrapper's own code does not structurally prevent it.
- There is no explicit origin/host/path allowlist — `fetch_once` accepts any `https://` URL, relying entirely on the caller to request only intended hosts.
- The body-truncation stream stop is against the PER-BODY cap only, not against the remaining GLOBAL byte allowance — a single very large response could in principle exceed the remaining global budget before the per-body cap kicks in, if the per-body cap is larger than what remains globally.
- There is no redirect-chain hop counter inside the wrapper itself (the "max 3 hops" rule was enforced by the calling script's own manual decisions this round, not by `wrapper.py`), and no in-flight cancellation when the 45-minute window or 10-minute wait is reached mid-request — both are checked only before starting a new attempt.
- The `timeout=20` passed to `requests` bounds each individual socket read/connect, not a hard total wall-clock cap on one exchange (a sufficiently slow drip could in principle exceed 20s in aggregate across many small reads before any single read times out).
- Default TLS verification (`verify=True`) is always used for real traffic, but this is "the default is on," not "every possible `verify` value or override path is actively guarded against" — the 5 self-tests prove the default-path behaviour and the one explicit non-default (`verify=<test CA path>`) case; they do not exhaustively prove every conceivable misuse is impossible.

None of this changed the actual run (6 data + 2 doc exchanges, all clean, no redirects, no truncation, no TLS failures) — these are documented as known code-level limitations for any future iteration that touches `wrapper.py`, not as things that went wrong this round.
