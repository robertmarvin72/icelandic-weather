### A1 IDBUTUR joins
Documented: IDBUTUR is the key between geometry and road state; geometry must be the newest version (check DAGSFERILS); a significantly changed section gets a new IDBUTUR; the last four digits are an informal version, usually bumped for all sections together; sections can disappear; geometry should be fetched when the ID set changes, not on every poll; the 2019 text says geometry is updated 4-6 times a year (2019 statement, not a measured SLA).
Verified in samples: all 13 chain IDs exist in both feeds; all chain features have DAGSFERILS 2026-10-07; `DagsButurBreyttist` for the chain is 2024-12-12 (3 IDs), 2025-11-20 (8 IDs) and 2026-06-02 (903010037, 253020037). The relation between DagsButurBreyttist and DAGSFERILS is not documented.
Consequences for the corrected report and next-task draft:
- The frozen 13-ID list is a dated snapshot, not a stable route definition. Store full 9-10 digit IDs (never strip the suffix), geometry DAGSFERILS and snapshot time with it; a chain ID missing from the state feed must yield "unavailable", not "no issue". Re-resolution by VEGNR/KAFLANR/name is an offline maintenance step, not a runtime guess.
- Type: the retained state feed gives IdButur as JSON floats (`506070037.0`); documentation, XML and WFS use integers. Normalise to an exact integer/string key and test the join on all 13 IDs.
- Keys are distinct: OBJECTID (feature), IDFERILL (path; documented to occur up to 3 times across thinning tiers), IDBUTUR (road-state section), IdPunktur (point event). Events and segments are many-to-one; never overwrite by IdButur.
- Direction: divided-road IDs are direction-specific. `252090037` is "Hellisheiði til austurs" (VEGHLUTI 7); the counterpart `902020037` "Hellisheiði til vesturs" (VEGHLUTI 6) exists in the same nationwide sample and is not in the chain. `253020037` also carries only VEGHLUTI 7.
