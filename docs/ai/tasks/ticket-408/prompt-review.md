### Owning the miss

Ripley's finding is real, and it's precisely the thing I got backwards in my Round 2 PASS. In "what's actually solid," I wrote that `useWeatherVoice.js`'s ref-driven `onVisible` meant "a stale captured callback can never record a stale episode" and treated CC's own test proving that a stale callback ends up crediting the *current* episode as confirmation of correct behavior. That's exactly wrong: crediting the current episode from an intersection event that was only ever observed against the *previous* episode's DOM node is not "safe," it's the bug — content gets marked shown without ever having been proven visible. I traced the mechanics by hand this round and confirmed it precisely: `notifiedRef` is a single ref shared across every effect incarnation of the component instance, reset to `false` at the top of each new effect run (i.e. for the *new* episode) — so a queued callback from the *old*, disconnected `IntersectionObserver` instance sails past the "already notified" guard, because that guard was just reset by the new episode's own effect setup, not by anything tied to the old observer itself. `observer.disconnect()` stops *future* observations but is not proof the browser's already-queued notification for that observer is cancelled — the correction prompt calls this out explicitly and correctly ("Do not assume disconnect removes already queued callbacks").

I also independently read Ripley's preserved repro (`outputs/ticket-408-weather-voice-evidence/WeatherVoice.review-repro.test.jsx`) rather than taking the "1 test failed, expected 0 received 1" claim on faith. It's a clean, minimal, correctly-constructed reproduction: a stub `IntersectionObserver` that records each callback it's given (so the test can grab the *first* one), render with `good_01`, rerender with `good_02` using the same `onVisible` reference, then manually invoke the captured *old* callback with `isIntersecting:true`. It imports the real `WeatherVoiceCard` and asserts `onVisible` was never called — which, by my own hand-trace of the actual component code, is provably false under the current implementation. This is a genuine, reproducible defect, not a theoretical concern.

### The second finding (hidden→visible with unchanged geometry) is also real

`WeatherVoiceCard`'s observer callback checks `document.visibilityState === "visible"` as an additional gate beyond `entry.isIntersecting`, but nothing in the component listens for `visibilitychange`. If the only intersection notification for a genuinely-displayed comment happens to fire while the tab is backgrounded, that notification is silently dropped (the visibility check fails, `notifiedRef` is never set), and nothing re-triggers a check when the tab becomes visible again unless the element's geometry also happens to change. A real, silently-lost exposure — correctly flagged.
