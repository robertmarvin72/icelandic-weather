### Verified from source (evidence grade: VERIFIED SOURCE unless stated)
- **Layout (likely root cause, INFERRED until browser-reproduced):** the panel (`RoutePlannerDetailsModal.jsx:146`) is `relative w-full max-w-3xl max-h-[85vh] overflow-hidden` with no `flex flex-col`. The content wrapper (`:202`) is `p-4 overflow-y-auto overscroll-contain` with no height constraint, so its height is `auto` and it can never become the scroller; the panel clips it and the footer (`:480`). That matches the issue symptom. The repo already has the correct shape: `HourlyForecastModal.jsx:289–308` (`flex flex-col overflow-hidden`, header, `min-h-0 flex-1 overflow-y-auto` body).
- **Lock/listener vs render guard:** the Escape effect (`:53–62`) and body-lock effect (`:64–80`) depend on `open` only, while render requires `open && candidate` (`:91`). With `open=true, candidate=null` both run with nothing visible, as Ripley suspected. It is not reachable from the card: `openDetails` returns on a falsy row (`RoutePlannerCard.jsx:227–231`) and `detailsCandidate` is never reset to null. So this is component-contract hardening, not a live trigger of the bug.
- **Inline `onClose`:** `RoutePlannerCard.jsx:1620` passes `onClose={() => setDetailsOpen(false)}`, a new function identity on every card render.
- **Backdrop is a focusable button:** `:144` is `<button aria-label="Close" className="absolute inset-0 …">`, first in DOM order, in the tab order.
- **Existing test contract:** `RoutePlannerCard.canonicalTone.test.jsx:158–163` finds the modal with `screen.queryByLabelText("Close modal")` (the header ✕, `:196`) and then the direct `document.body` child containing it. `queryByLabelText` throws on multiple matches.
- **Tooling:** Tailwind is v4 (`^4.3.3`; `tailwind.config.js` is a leftover), React 19 (`useId` available), `<StrictMode>` wraps the app (`src/main.jsx:34`), `@playwright/test` is already a devDependency, evidence folders `outputs/ticket-4xx-browser-evidence` are an established convention.
- **Opener sites:** two (`RoutePlannerCard.jsx:1371`, `:1513`); the opener is inert in preview mode (`isPreview = !!routeFeature?.preview && !isPro`, `:186`; `:228`).

### Conditions

**J2 — Layout fix follows the in-repo precedent.** Panel `flex flex-col`; header and footer `shrink-0`; content `min-h-0 flex-1 overflow-y-auto` (keep `overscroll-contain`); footer must be a sibling outside the scroller. Use Tailwind v4-valid utilities written as complete static class strings (the scanner does not see built-up names). Keep a `vh` baseline and add `dvh` as progressive enhancement, so a browser without `dvh` support does not lose `max-height` altogether; confirm in the built `dist` CSS that the emitted rule exists. Rationale (INFERRED, not provable in desktop emulation): on mobile Safari `85vh` is 85% of the large viewport, which can still exceed the visible area when browser chrome is showing, so the flex fix alone may leave the footer under the toolbar on a real phone. No fixed pixel subtraction, no hiding or truncating content. Short landscape (e.g. 667×320) leaves roughly 100 px for content after header and footer; if the scroll region is unusably small in the screenshot, report it with evidence and STOP for a Ripley decision rather than redesigning header/footer.

**J3 — Dialog semantics, with the #441 helper kept working.** `role="dialog"`, `aria-modal="true"`, `aria-labelledby` pointing at the title element via `useId`, on the panel (not the overlay). New hooks must be declared above the early returns at `:91–92`. Do not change or duplicate the string `aria-label="Close modal"` and keep the portal as a direct child of `document.body` containing it: `canonicalTone` depends on both, and `queryByLabelText` throws if two elements match. Replacing it with `t("close")` would be an edit to an existing #441 test and needs an explicit Ripley decision. The hardcoded English `"Close"`/`"Close modal"` labels are a pre-existing i18n gap (same in `LoginModal.jsx`); report as a follow-up candidate, do not fix here. **J4 — Backdrop out of the tab order, click-to-close preserved.** The backdrop button must not be a tab stop or an initial-focus candidate, and must not be exposed as a second "Close" control. Implement however lint allows (non-button element with click handler, or equivalent) and prove: backdrop click closes once, a click inside the panel does not close.

**J5 — Focus lifecycle keyed to "dialog actually rendered", not to `onClose` identity (MEDIUM).** `WeatherVoiceShareDialog.jsx:165–209` is a usable precedent (trap, `previouslyFocusedRef`, `document.contains` fallback) but its trap effect has `[onClose]` as a dependency and assumes mount-only, because its parent stabilises the callback. This modal is always mounted and returns `null` when closed, and the card passes an inline `onClose` (above). Copying the precedent verbatim would re-run the effect on every card render: refocus the first control (focus stealing) and recapture "previous focus" as an element inside the dialog, breaking focus return. Requirements: one derived `isRendered = open && !!candidate` (plus the existing `document` guard); focus capture, initial focus, trap, Escape handling and body lock key only on `isRendered`; latest `onClose` held in a ref. Test: rerender with a new `onClose` identity and with a different candidate object while open → focus does not move, restore target unchanged. Test the whole open/close cycle inside `<StrictMode>` (dev double-invokes effects) → focus ends on the opener, body styles restored, listeners balanced.

**J6 — Initial focus must leave keyboard users able to scroll (MEDIUM).** Arrow/PageDown/Space scroll the focused element's scrollable ancestor. If initial focus lands on the header ✕ or the panel itself, neither is inside the new scroller, so a keyboard-only user cannot scroll the long content (the first focusable inside the content is the advanced toggle near the bottom, and Chrome only makes scrollers tabbable when they have no focusable children). Choose the initial focus target (for example the scroll region with `tabIndex={-1}`, or a labelled focusable scroll region) so that ArrowDown/PageDown changes `scrollTop` immediately after opening, without clicking. Browser evidence must show this. Trap rules: recompute focusable elements at keydown time (the advanced disclosure changes the set), exclude disabled and `tabindex="-1"`, and if `document.activeElement` is outside the dialog (for example after clicking non-interactive dialog text), Tab/Shift+Tab must re-enter at first/last. No `inert` on the rest of the page is required (global change).

Use `focus({ preventScroll: true })` and verify page `scrollY` is unchanged after close.
